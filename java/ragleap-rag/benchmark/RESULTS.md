# Cross-backend benchmark and failure-mode matrix (Java port)

Answers issue #565: do the Java vector backends return comparable results, and how do they behave on edge cases? Run on 2026-10-03. Every number below is generated by `generate_report.py` from the raw files in `results/`.

## Summary

- **Retrieval is identical** on FAISS, pgvector, Qdrant and Weaviate: the same top-10 documents for all 60 queries (overlap@10 = 1.000 against an exact float64 scan), and each finds the source paragraph exactly as often as the exact scan.
- The benchmark found **two score-scale bugs** (FAISS and Weaviate returned raw cosine in [-1, 1] while pgvector and Qdrant return [0, 1]); both are fixed (#574, #576).
- The failure-mode matrix (19 cases x 4 backends) found **three more bugs** in Weaviate, FAISS and Qdrant, all fixed (#584, #585). After the fixes, 15 cases behave the same on all four backends and 4 differ in documented ways.
- **Not covered:** Milvus and Pinecone (no infrastructure to run them live; they are tested against HTTP stubs only), and approximate-search recall at scale (see Limits).

## Method

- **Data:** SQuAD v1.1 dev set (CC BY-SA 4.0). Every 7th paragraph is a document (296 documents); the first question of 60 of them is a query whose gold document is the paragraph it was written from.
- **Vectors:** embedded once with nomic-embed-text (Ollama), 768 dimensions, then the same vectors are stored in every backend, so embedding noise cannot affect the comparison.
- **Ground truth:** an exact float64 cosine scan computed in the test itself; no backend is used as its own reference.
- **Metrics:** overlap@10 (share of the exact top-10 returned), top-1 agreement, gold hit@k (does the backend find the source paragraph), the score range, and the deviation of each returned score from (cosine + 1) / 2.
- **Environment:** Java `openjdk version "21.0.12.1" 2026-08-18`; Qdrant 1.19.1; Weaviate 1.27.0; pgvector 0.8.6 on Postgres; 1 CPU, 3.8 GB RAM.

## Retrieval results (after the fixes)

Exact float64 scan: gold hit@1 / @5 / @10 = 0.883 / 0.933 / 0.983.

| Backend | overlap@10 | top-1 agreement | gold hit@1 / @5 / @10 | score range | deviation from (cosine+1)/2, mean / max | median latency |
|---|---|---|---|---|---|---|
| FAISS | 1.000 | 1.000 | 0.883 / 0.933 / 0.983 | 0.744 to 0.949 | 0.00003 / 0.00005 | 1.0 ms |
| pgvector | 1.000 | 1.000 | 0.883 / 0.933 / 0.983 | 0.744 to 0.949 | 0.00003 / 0.00006 | 4.2 ms |
| Qdrant | 1.000 | 1.000 | 0.883 / 0.933 / 0.983 | 0.744 to 0.949 | 0.00003 / 0.00005 | 7.9 ms |
| Weaviate | 1.000 | 1.000 | 0.883 / 0.933 / 0.983 | 0.744 to 0.949 | 0.00003 / 0.00005 | 33.9 ms |

Latency is indicative only: one shared CPU with heavy steal time, a 296-document corpus, and run-to-run variation (Weaviate's p95 varied several-fold between runs).

## Failure-mode matrix

Each case runs on a fresh collection and records what happens (result or exception) without asserting, so differences show up. In the comparison, exception class names are ignored (pgvector's driver raises a PSQLException, a subclass of SQLException).

### Same behaviour on all four backends (15 cases)

| Case | What was tested | Result |
|---|---|---|
| `empty-collection-search` | search before any data is stored | 0 results |
| `topk-larger-than-data` | topK=100 with 3 chunks stored | 3 results |
| `filter-matches-nothing` | metadata filter k=nope (nothing has it) | 0 results |
| `filter-matches-all` | metadata filter k=v (every chunk has it) | 3 results |
| `delete-missing-document` | deleteDocument for an id that was never stored | returned false |
| `filename-of-missing-document` | getDocumentFilename for an unknown id | present=false |
| `wrong-dimension-insert` | insert a 3-dim vector into a 4-dim collection | EXC: expected 4 dimensions, not 3 |
| `unicode-and-quotes` | unicode, quotes, backslash and newline in filename, metadata and text | filename roundtrip=true, text roundtrip=true, filter on that value -> 1 hit(s) |
| `init-schema-twice` | initSchema called a second time | second call: ok |
| `pagination` | listDocuments(limit 2, offset 0) and (limit 2, offset 2) with 3 documents | 2 then 1 |
| `delete-then-search` | delete document A, then search | deleted=true, hits=2, deleted doc still returned=false |
| `score-identical-vs-opposite` | scores of an identical and an opposite vector | identical=1.0000, opposite=0.0000 |
| `filter-on-unknown-key` | metadata filter on a key that no chunk has (nokey=x) | 0 results |
| `failed-insert-then-retry` | insert with a wrong-dimension vector (fails), then retry the same chunk correctly | wrong-dim insert=EXC: expected 4 dimensions, not 3, retry=ok, search=1 hit(s), chunks listed=1 |
| `search-after-deleting-everything` | delete all three documents, then search and list | 0 results, documents listed=0 |

| Weaviate | OK doc#1=ok, doc#2=EXC SQLiteException: [SQLITE_CONSTRAINT_PRIMARYKEY] A PRIMARY KEY constraint failed (UNIQUE constraint failed: documents.id), chunk#1=ok, chunk#2=EXC SQLiteException: [SQLITE_CONSTR... |

FAISS and pgvector accept a second chunk with the same document and chunk index (both are returned by a search). Qdrant and Weaviate reject it, because their point ids are derived from documentId:chunkIndex and their local table has a unique key on it. A duplicate document id is rejected by all four.

#### `wrong-dimension-query`: search with a 3-dim query against 4-dim data

| Backend | Result |
|---|---|
| FAISS | OK 0 results |
| pgvector | EXC PSQLException: ERROR: expected 4 dimensions, not 3 |
| Qdrant | OK 0 results |
| Weaviate | OK 0 results |

pgvector raises an error; FAISS, Qdrant and Weaviate return an empty list.

#### `zero-vector`: insert an all-zero embedding, then search

| Backend | Result |
|---|---|
| FAISS | OK hits=1, score=0.5 |
| pgvector | OK hits=0 |
| Qdrant | OK hits=1, score=0.5 |
| Weaviate | OK hits=1, score=0.5 |

pgvector returns nothing for an all-zero vector (cosine similarity is undefined for it); the other three return it with score 0.5. Embedding models do not normally produce zero vectors.

#### `server-unreachable`: backend pointed at a port with nothing listening

| Backend | Result |
|---|---|
| FAISS | N/A (in-process, no server) |
| pgvector | EXC PoolInitializationException: Failed to initialize pool: Connection to localhost:1 refused. Check that the hostname and port are correct and... |
| Qdrant | EXC SQLException: Qdrant request failed: GET /collections/x |
| Weaviate | EXC SQLException: Weaviate request failed: GET /v1/schema/X |

pgvector raises the connection pool's unchecked PoolInitializationException; Qdrant and Weaviate raise SQLException. Callers should catch RuntimeException as well as SQLException for pgvector connection failures. FAISS runs in-process and has no server.

## Bugs found and fixed

| Finding | Fix |
|---|---|
| Weaviate returned raw cosine in [-1, 1] | #574 |
| FAISS returned raw cosine in [-1, 1] | #576 |
| FAISS, Qdrant and Weaviate accepted or mishandled a wrong-dimension vector on insert (FAISS stored it silently) | #584 |
| Weaviate raised a GraphQL error when searching an empty collection or filtering on a key no chunk had yet | #585 |
| Qdrant and Weaviate left a local row behind when the server write failed, so the chunk could not be retried | #585 |

The Python `FaissBackend` and `PineconeBackend` still return raw cosine scores (issue #577).

## Limits

- 296 documents is small: Qdrant and Weaviate use HNSW indexes, but at this size they behave like an exact scan. This measures integration correctness, score comparability and retrieval quality, **not approximate-search recall at scale**.
- 60 queries from one dataset and one embedding model.
- One known gap: if a server applies a write but the response is lost, retrying the same chunk can still fail on Weaviate.
- Milvus and Pinecone are not benchmarked.

## Reproduce

```bash
python3 java/ragleap-rag/benchmark/prepare_dataset.py            # downloads SQuAD, embeds with Ollama, writes /tmp/bench/corpus.json
cd java/ragleap-rag
RAGLEAP_BENCH_DIR=/tmp/bench RAGLEAP_BENCH_BACKENDS=faiss,pgvector,qdrant,weaviate mvn test -Dtest=CrossBackendBenchmarkTest
RAGLEAP_BENCH_DIR=/tmp/bench RAGLEAP_BENCH_BACKENDS=faiss,pgvector,qdrant,weaviate mvn test -Dtest=FailureModeMatrixTest
```

Needs Qdrant on :6333, Weaviate on :8081 and a Postgres with pgvector and an empty database `ragleap_java_bench` on :5433 (see the test sources for the connection settings).
